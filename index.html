Research result · September 2026

A language substrate emerged. Working memory did not.

The useful result is not that Founder V0 is “smart.” It is that we now know exactly what a small Stark-native transformer learns, what it fails to learn, and what the next architecture must improve.

Language generalization9.462 → 3.893

Untouched held-out loss fell by 5.569 from the random t=0 model. Perplexity fell from 12,861.6 to 49.07.

Reasoning baseline40%

10 deterministic multiple-choice probes. Logic, opposites, ordering and quantity passed; arithmetic and sequence probes did not.

Stable knowledge25%

2 of 8 stable factual probes passed. Founder is not an authoritative knowledge store.

Exact context recall25%

Chance-level across 64, 128, 256, 512, 768 and 960-token probes. A 1024-token attention window is not the same as usable memory.

Primary finding

Context length ≠ memory.

Founder V0 can technically attend across a 1024-token physical window, yet exact secret-code recall remains at chance. This gives Stark a clean experimental target: add persistent state, recurrent memory, retrieval and cells without destroying the language capability we already earned.

Architecture

Founder is an organ, not the organism.

Stark's long-term design remains a local-first digital being: neural language substrate, persistent memory, recurrent state, specialized cells, routing, governance and host-controlled action.

Local first

Training and runtime are designed to run on owned hardware. Founder V0 was trained and evaluated on an RTX 3050 Laptop GPU.

Measure before layering

RMT, state-space models, sparse attention, retrieval and cells can be combined later—but only after each mechanism proves a measurable gain.

Memory is state

Long-lived context should not depend on replaying the entire transcript. Relevant state is activated; irrelevant state can remain dormant.

Fail closed

Tokenizer identity, dataset identity, checkpoints, resume state and release promotion are verified rather than assumed.
